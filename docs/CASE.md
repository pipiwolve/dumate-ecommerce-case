# ShopFlow v2.6 完整业务 Case

## 1. 客户与决策

客户正在准备 8 月 15 日限时促销。客户项目经理需要判断版本是否偏离计划，
技术负责人需要定位代码风险并安排处理。DuMate 在周四 18:00 冻结同一批证据，
再为两个角色生成不同信息密度的报告。

## 2. 本期计划基线

GitHub Milestone `v2.6 限时促销稳定性` 是计划基线。Issue 状态表达计划进度，
PR、Commit、Diff、Review 和 Check Run 只作为完成与风险证据。代码提交数量不能
直接代表业务进度。

| 事项 | 状态 | 进度 | 报告含义 |
|---|---|---:|---|
| FEAT-101 库存预占模块 | 已完成 | 100% | 核心能力已进入 main |
| BUG-102 并发超卖 | 阻塞 | 45% | 首次修复仍失败，阻塞发布 |
| BUG-103 取消订单释放 | 已完成 | 100% | 回归缺陷已闭环 |
| PERF-104 N+1 查询 | 审查中 | 90% | CI 通过，等待 owner review |
| SEC-105 后台库存权限 | 待开始 | 0% | 需安全专家给出最小控制方案 |
| CHORE-106 缓存调优 | 未关联 | - | 计划外修改，需确认或补 Issue |

加权进度为 65%，健康状态为“有风险”。

## 3. 开发过程

1. 开发者合并 FEAT-101，实现库存预占、支付确认和超时释放。
2. BUG-103 暴露取消订单会错误扣减库存，修复提交使 release 幂等。
3. QA 并发压测发现 BUG-102：库存为 1 时两个订单都预占成功。
4. 首次修复仅锁住写入，未保护 check-then-act；回归测试仍得到 `available=-1`。
5. 评审意见引用库存并发规范和历史超卖事故，推荐一致性专家王海介入。
6. PERF-104 提供批量库存读取，测试通过但仍等待模块 owner review。
7. DuMate 发现 `chore/cache-tuning` 没有关联 Issue，且改变库存缓存语义。

## 4. 双角色输出

技术负责人版需要保留 PR、SHA、失败断言、模块、Diff 规模、知识来源和专家建议。
客户项目经理版只呈现里程碑、交付影响、阻塞原因、责任人与下一步，不暴露内部
代码细节或未经确认的责任判断。

## 5. Demo 与正式上线差异

Demo 允许自动生成并推送两份 PPT。正式上线时，客户版必须由内部项目经理审核；
无人确认时只保留内部草稿，不自动外发。严重阻塞和主分支检查失败应即时提醒，
完整 PPT 仍按固定周期生成。
